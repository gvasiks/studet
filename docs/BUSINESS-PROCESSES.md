# Studet — бизнес-процессы

Состояние на 2026-09-21. Описано то, что **построено и работает**, что построено
частично и что только спроектировано. Для каждого процесса указано, кто его
выполняет, чем он запускается, что на выходе и чем контролируется. Цифры взяты из
базы и репозитория на эту дату.

Обозначения: ✅ работает · 🟡 работает частично · ⏳ спроектировано, не построено.

## 1. Продукт в одном абзаце

Веб-сервис для выбора вуза в Латвии. **Аудитория А** — латвийские выпускники
(латышский язык, бесплатно): анкета → каталог → расчёт конкурсного балла → обратный
поиск «куда я прохожу». **Аудитория Б** — иностранные абитуриенты (английский,
платно) — не начата. Общая база: программы, требования, сроки, стоимость.
Главный принцип: **никакого факта без источника и даты проверки, а критичные
факты подтверждает только человек** (правила 5 и 6 из `CLAUDE.md`).

## 2. Роли

| Роль | Что делает | Чего не делает |
|---|---|---|
| **Владелец** (1 человек, ~12 ч/нед, из них ~5 на код) | Решает: публикация, хостинг, домен, оператор данных. Подтверждает факты (формулы, сроки, типы отбора, направления). Задаёт вопросы приёмным комиссиям. Разрешает скачивание документов | — |
| **ИИ-ассистент (Claude)** | Пишет код, разбирает документы, готовит листы сверки, ведёт документацию, показывает план до кода | Не подтверждает факты сам (`verified_at` — только человек). Не публикует сайт. Ключ `service_role` не читает и не передаёт |
| **Автоматика** | GitHub Actions (сбор каталога по расписанию, CI), ограничения БД (нельзя подтвердить формулу без протокола источника), RLS (публично читаются только допустимые строки) | Не принимает решений о фактах |

## 4. Процессы

### П1. Сбор каталога программ ✅

**Цель.** Держать в базе актуальный список программ 44 учреждений: название,
уровень, язык, форма, длительность, город, стоимость, бюджетные места.

**Запуск.** GitHub Actions `Scrape catalog`: каждый понедельник 01:00 UTC
(тайм-аут 120 минут) и вручную кнопкой. Локально — `python src/main.py`.

**Кто.** Автоматика. Владелец один раз задаёт секреты и переменную
`SCRAPER_CONTACT` в GitHub.

**Шаги.**
1. Для каждого из 25 источников (сборщик на вуз или на группу вузов; колледжи и
   филиалы, а также дополнения для LBTU, DU, Turība, RISEBA, RSU — из
   национальной базы NIID) собираются черновики `(вуз, [программы])`.
2. Обход «вежливый»: честный User-Agent с контактом из `SCRAPER_CONTACT`,
   `robots.txt` соблюдается, пауза не меньше 1,5 с на домен (у NIID — 10 с по
   его `Crawl-delay`), картинки и шрифты не грузятся.
3. **Проверка нижнего порога.** Если источник вернул программ меньше, чем в
   `MIN_PROGRAMME_COUNT`, он не сохраняется, а прогон завершается ошибкой:
   тихая потеря половины каталога недопустима.
4. Запись в Postgres сервисным ключом: вставка или обновление строк, **поле
   `verified_at` не трогается никогда**.
5. Ошибки копятся по всем источникам; в конце ненулевой код выхода, чтобы
   расписание показало красный статус.

**Результат.** 44 учреждения, 900 программ (бакалавриат 337, колледж 153,
магистратура 309, докторантура 101).

**Контроль.** Порог полноты; отчёт по каждому источнику (запросы, кэш, пропуски);
данные без даты проверки помечаются на сайте «извлечено автоматически —
сверьтесь с сайтом вуза».

**Оговорка.** Расписание настроено и секреты добавлены, но подтверждения, что
запланированный запуск уже отработал в GitHub, в этой сессии нет — владелец
должен один раз запустить workflow и посмотреть результат.

**Где.** `pipeline/src/main.py`, `pipeline/src/sources/`, `pipeline/src/polite.py`,
`.github/workflows/scrape-catalog.yml`.

### П2. Контроль полноты каталога ✅

**Цель.** Убедиться, что сборщики не теряют программы.

**Шаги.** Скрипт сравнивает число программ у нас и в NIID по каждому учреждению и
уровню, печатает расхождения (`docs/AUDIT-COMPLETENESS.md`). Запускается после
добавления нового источника и перед релизами.

**Результат последнего прогона.** Расхождения по LBTU, DU, Turība, RISEBA — ноль;
у RSU разница по магистратуре и докторантуре объяснена намеренно (добор).

**Где.** `pipeline/src/audit_completeness.py`.

### П3. Скрытие пропавших программ ✅

**Цель.** Не показывать людям программу, которую вуз убрал с сайта, но и не
удалять её из-за одного сбоя сборщика.

**Шаги.** После успешного и прошедшего порог прогона источника у программ, которых
в нём нет, растёт счётчик `missed_runs`. Политика доступа отдаёт публично только
строки с `missed_runs < 2`. Если программа вернулась — счётчик обнуляется.

**Результат.** Сейчас скрыта 1 программа.

**Где.** `programme.missed_runs`, политика `programme_public_read`, `main.py`.

### П4. Разметка направлений программ 🟡

**Цель.** Отнести каждую программу к направлению (здоровье, право, ИТ…),
чтобы фильтровать каталог по интересам и показывать данные о выпускниках.

**Шаги.** Правила по ключевым словам названий (латышских и английских) дают
черновую разметку; спорные программы остаются без направления и выводятся в
отчёт (сейчас неразмеченных 9). Человек подтверждает разметку в Supabase Studio.

**Результат.** 891 черновая запись; подтверждено 0. Пока нет подтверждения, блок
«что стало с выпускниками» на сайте скрыт.

**Где.** `pipeline/src/programme_fields.py`, `seed_programme_fields.py`.

### П5. Получение документа-источника ✅

**Цель.** Каждая формула опирается на утверждённый документ вуза с номером,
датой и неизменной копией — а не на страницу сайта и не на чью-то память.

**Шаги.**
1. Найти актуальные правила приёма вуза (для 2026/27 — PDF или сохранённая
   страница). Источник коэффициентов — **утверждённый документ**, а не веб-страница
   (у РТУ две страницы сайта давали разные веса).
2. **Спросить владельца о скачивании** (имя файла, источник, размер) и получить «да».
3. Положить копию в `docs/source-documents/<вуз>/` с датой получения и записать
   в README таблицы: откуда, номер и дата документа, сколько формул из него.
4. Хэш SHA-256 копии считается программой при записи формулы, вручную не
   вносится; файлы закреплены в git «как есть» (`.gitattributes`), чтобы перенос
   строк не менял хэш.

**Результат сейчас.** Копии документов ЛУ (2025/26 и 2026/27), RSU, Ventspils,
РТУ (страница, PDF у РТУ нет), LBTU, DU.

**Контроль.** Ограничение в БД: формулу нельзя подтвердить без адреса, номера,
даты документа, пути копии и хэша. Страница `/verification` показывает
«Protokols nepilns» и предупреждает о документе старше 12 месяцев.

**Где.** `docs/source-documents/`, `seed_formulas.source_protocol()`.

### П6. Извлечение и загрузка формул ✅

**Цель.** Перенести конкурсные формулы из документов в базу как **данные**
(вычислитель один для всех вузов), без ручного переписывания.

**Шаги.**
1. Парсер документа (`formulas_lu.py`, `formulas_rsu.py`) режет его на блоки
   программ и выделяет слагаемые «коэффициент × предмет».
2. **Проверки на каждое слагаемое:** арифметика (k × m = p) и сумма баллов по
   шкале вуза (ЛУ — 1000, RSU — 100). Не сошлось — формула не берётся.
3. Автоматика **ничего не додумывает**. Если документ не определяет, как считать
   (альтернативы «физика или химия», варианты «1.a / 1.b», разные веса у
   подпрограмм), блок идёт в отчёт с причиной и в базу не попадает.
4. Запись **черновиком**: слагаемые, признак необязательного слагаемого («ja nav
   CE, tad 0»), дословный текст блока (`source_excerpt`), протокол источника.
   Запуск по умолчанию — «сухой» (без `--apply`); подтверждённые формулы не
   перезаписываются.
5. Формулы прошлого учебного года закрываются датой `valid_to`; нет формулы
   честнее, чем формула прошлого года.
6. Вопросы, на которые ответит только вуз, копятся в списке для приёмных комиссий.

**Результат.** ЛУ — 47 формул из 65 блоков; RSU — 16 приложений документа (18 программ каталога);
Ventspils — 8 из 13 (магистратура идёт по другой модели); РТУ RBS — 2.
Действующих формул 75; закрыто 26 формул 2025/26.

**Не выражается моделью (открыто).** РТУ п. 31.1 (около 60 программ:
«физика и/или химия» и нет направления у программ в каталоге); LBTU (множитель
×1,25 для высшего уровня, «CE или оценка аттестата»); DU («CE или экзамен в
аттестате», таблица не разбирается). Модель уже умеет: необязательное слагаемое
и среднее по CE «с учётом уровня».

**Где.** `pipeline/src/formulas_lu.py`, `formulas_rsu.py`, `formula_drafts.py`,
`seed_formulas.py`; таблицы `formula`, `formula_term`, `formula_gate`.

### П7. Подтверждение фактов человеком ✅ (механизм) / 🟡 (объём)

**Цель.** Ни одна формула, срок, тип отбора и направление не станут публичными,
пока человек их не проверил (правило 6).

**Что подтверждает только человек:** конкурсная формула, срок подачи, стоимость и
бюджетные места, требование к языку, через кого подача.

**Шаги.**
1. Открыть `/verification`: очередь показывает, что ещё не подтверждено, что
   заблокировано (неполный протокол, старый документ) и долю подтверждённых формул.
2. Открыть источник и сверить: у формул рядом лежит дословный текст блока.
3. Проставить `verified_at` и `verified_by` в Supabase Studio (SQL или форма).
4. Публично читаются только подтверждённые строки (RLS): калькулятор и обратный
   поиск не увидят неподтверждённое.

**Состояние.** Формул подтверждено 72 из 75. Очередь 900 записей: направления 891,
типы отбора 4, сроки подачи 2, формулы 3.

**Разовое исключение 2026-09-20.** По прямому разрешению владельца 72 формулы
подтверждены одним запросом после предварительной сверки коэффициентов с
документами (ЛУ — независимо по дословным блокам; RSU, Ventspils, РТУ — по тексту).
`verified_by` содержит пометку об этом. Это **не новый порядок**: скрипты пайплайна
`verified_at` по-прежнему не трогают; попытка записи ассистента через сервисный
ключ была заблокирована фильтром разрешений и повторяться не должна.
Не подтверждены: две программы ЛУ с отдельной заочной формулой и Elektronikas
inženierija (Ventspils, максимум 110 при «шкале 100»).

**Где.** `src/app/[locale]/(site)/verification/`, `src/lib/verification-queue.ts`,
миграции `formula_verified_needs_protocol`, вид `verification_queue`.

### П8. Годовой цикл сверки ⏳

**Цель.** Раз в год обновить сроки, требования и формулы без переписывания кода.

**Якорь.** По закону вузы **до 30 ноября** публикуют правила и дату начала
регистрации на следующий год (Augstskolu likums, ст. 46 (5); MK Nr. 846, п. 3).

**Шаги (запланированы на декабрь).**
1. После 30 ноября пройти по вузам: новые документы правил.
2. П5 → П6: копия документа, разбор, запись новыми строками (новый `valid_from`,
   старая формула закрывается `valid_to`).
3. Собрать сроки подачи (Turība открывает приём 5 января) и типы отбора.
4. П7: подтверждение новых формул и сроков; в первую очередь ЛУ и Ventspils
   (сейчас они на правилах 2026/27).
5. Повторно вычитать страницы про права и приватность (в законе есть поправки,
   которые вступают 31.12.2026).

**Оценка.** 6–8 часов разработки и подтверждение владельцем в декабре–феврале.

### П9. Пользовательский путь (аудитория А) ✅

**Цель.** Ответить абитуриенту на «что мне подходит и куда я реально прохожу»,
не собирая его данных.

**Шаги пользователя.**
1. **Анкета** (6 шагов, без регистрации): экзамены, интересы, финансирование,
   город, язык, форма обучения. Интересы, город, язык и форма попадают в адрес как
   фильтры; **экзамены не уходят никуда**.
2. **Каталог** (`/programmes`): поиск, фильтры, сортировка; карточка программы с
   метками «проверено вручную <дата>» или «извлечено автоматически»; данные о
   выпускниках (когда подтверждены).
3. **Калькулятор программы:** ввод процентов и уровня (высший/оптимальный/общий),
   расчёт в браузере по формуле из базы, разбор «из чего сложился балл», ссылка на
   правила и оговорка «решает вуз». Калькулятор виден только при подтверждённой
   формуле.
4. **Обратный поиск `/match`:** экзамены вводятся один раз, результат разложен по
   группам: «балл можно посчитать», «порог не пройден», «нужен ввод испытания или
   аттестата», «не хватает экзаменов». Сортировка по вузу и названию, а не по
   баллу: шкалы вузов несопоставимы; «пройдёшь ли» в процентах не показывается.
5. **Избранное:** список программ только в `localStorage` устройства, сравнение
   таблицей.

**Что процесс намеренно не делает.** Не хранит и не отправляет экзамены
несовершеннолетних; не ранжирует вузы; не предсказывает шансы; не даёт
рекомендаций по личности; не подаёт документы за абитуриента.

**Где.** `src/app/[locale]/(site)/{survey,programmes,match,favorites}`,
`src/lib/{formula,match}.ts`.

### П10. Данные о выпускниках 🟡

**Цель.** Показать на карточке, что стало с выпускниками направления в вузе:
доля работающих, медиана дохода (не показывается при менее чем 30 занятых).

**Шаги.** Ежегодная загрузка открытого набора данных (data.gov.lv, IZM/CSP) →
привязка к вузу и направлению → показ на карточке с пометкой, что это данные по
направлению, а не по программе.

**Состояние.** Загружено 3309 записей. Публичный показ включается после
подтверждения направлений (П4).

**Где.** `pipeline/src/import_graduate_outcomes.py`, `graduate_outcomes.py`.

### П11. Правовая информация и приватность 🟡

**Цель.** Дать абитуриенту проверяемое изложение его прав и терминов и честно
описать обработку данных.

**Шаги.**
1. Тексты `/rights`, `/glossary`, `/privacy` (LV и EN) пишутся **по дословным
   нормам** (MK Nr. 846 в редакции на 30.12.2025, Augstskolu likums, закон о
   обработке данных физических лиц, ст. 33 — возраст согласия 13 лет).
2. Для владельца — таблица «наш текст ↔ дословная норма»
   (`docs/checks/RIGHTS-PAGE-SOURCES.md`) и список «что должно быть правдой к
   публикации» (`docs/PRIVACY-CHECKLIST.md`).
3. Утверждение, которое не нашлось в тексте нормы, на страницу не попадает
   («запрет заключать договоры до официальной даты» — только пересказ ИЗМ, в
   нормах его нет).
4. Оператор данных и e-mail задаются переменными окружения; пока не заданы,
   страница показывает их имена, чтобы пустое место было видно.

**Состояние.** Тексты и страницы готовы локально; не готово: имя оператора и
контакт (от владельца), вычитка латышского, решение по сроку хранения адресов

### П12. Контроль качества релиза ✅

**Цель.** Каждый релиз соответствует стандартам проекта: безопасность (OWASP
Top 10:2025), доступность (WCAG 2.2 AA), скорость (Core Web Vitals).

### П14. Планирование и управление охватом ✅

**Цель.** Уложиться в три внешние даты с одним разработчиком: **5 января 2027**
(анкета + каталог, Turība открывает приём), **май 2027** (калькулятор ЛУ, РТУ,

**Правило.** При отставании режется охват, а не качество: два вуза точно лучше
восьми приблизительно. Порядок отреза заранее записан в `docs/WORKPLAN.md`.

**Шаги каждую неделю.** Пересчитать часы (5 ч кода в неделю), сверить с планом,
отметить сделанное и остаток, решить, что режем. Открытые решения владельца
ведутся списком.

### П15. Порядок работы с ИИ-ассистентом ✅

1. **Сначала план, потом код.** Маленькие шаги, один смысл — один коммит.
2. Скучное и хорошо документированное выигрывает у элегантного; библиотека
   добавляется только с ответом «сколько весит и что будет без неё».
3. Ассистент **не подтверждает факты** и не хранит секреты; скачивание
   документов — по «да» владельца; публикация вовне — только по прямой команде.
4. Разрешение на исключение из правила действует **один раз и не переносится**
   (как разовое подтверждение 72 формул).
5. Сообщения об итогах — с числами, проверками и оговорками: что сверено, что нет.
