# Гид по тестированию Studet

Один документ: что за проект, как его запустить, и подробный чек-лист по
каждой странице — с точным текущим состоянием данных на 2026-09-25, чтобы
при тестировании было понятно, где реально баг, а где просто ещё не
наполнено или не подтверждено. Цифры ниже сняты с живой базы в момент
написания и будут расходиться с реальностью уже через неделю — если что-то
из «текущего состояния» не совпадает с тем, что вы видите, вернитесь к
`docs/PLAN-2026-09-21.md` (раздел 10) за последним статусом, а не считайте
это ошибкой в гиде.

## 1. Что это за проект (коротко)

Веб-сервис, помогающий выпускникам латвийских школ выбрать вуз: анкета →
список подходящих программ → калькулятор конкурсного балла. Бесплатно, без
регистрации, ничего не сохраняет на сервере. Второй, платный продукт для
иностранных абитуриентов — намеренно не начат, о чём честно сообщает баннер
на английских страницах. Полная модель — `CLAUDE.md` в корне репозитория,
это основной источник правды по правилам и ограничениям проекта.

## 2. Как запустить локально

```bash
npm install
cp .env.local.example .env.local
# заполнить NEXT_PUBLIC_SUPABASE_URL и NEXT_PUBLIC_SUPABASE_ANON_KEY
# значениями из Supabase Dashboard -> Settings -> API
npm run dev
```

Открывается на `http://localhost:3000` (см. `.claude/launch.json`). Без
заполненных переменных Supabase сайт соберётся, но все страницы, читающие
каталог, упадут с ошибкой — это не баг, а отсутствующая конфигурация.

Полезные флаги в `.env.local` (закомментированы в `.env.local.example`,
описание каждого — там же):
- `MATCH_FIXTURE=1` — на `/match` показывает выдуманные формулы вместо
  реальных (для проверки вёрстки, требует перезапуска `next dev`);
- `PRIVACY_CONTROLLER_NAME`/`PRIVACY_CONTACT_EMAIL` — без них `/privacy`
  показывает имя переменной вместо контакта (тоже не баг, это специально).

## 3. Карта страниц

Каждый маршрут существует в двух локалях — `/lv/...` и `/en/...`. Ниже без
префикса локали.

| Маршрут | Что это | Клиентский JS? |
|---|---|---|
| `/` | Главная | Нет (правило 4 CLAUDE.md) |
| `/programmes` | Каталог (фильтры, поиск, сортировка) | Нет — фильтры через query-параметры |
| `/programmes/[вуз]/[программа]` | Карточка программы | Нет |
| `/programmes/[вуз]/[программа]/calculator` | Калькулятор конкурсного балла для программы | Да (HeroUI) |
| `/survey` | Анкета (6 шагов) | Да (HeroUI) |
| `/match` | Обратный поиск — ввёл экзамены, увидел, где балл считается | Да (HeroUI) |
| `/favorites` | Список избранного (только `localStorage`) | Да |
| `/glossary` | Глоссарий терминов приёма (со ссылкой на правовой источник каждого) | Нет |
| `/rights` | Права абитуриента (по нормам закона) | Нет |
| `/privacy` | Политика конфиденциальности | Нет |
| `/verification` | Внутренний инструмент — очередь неподтверждённых фактов | Нет; текст только на латышском, `noindex` |

      (см. раздел 4) — если сбой базы, бейдж просто не показывается, страница

- [ ] Мобильная раскладка (375px) — без горизонтального скролла и наплывов.

## 6. Чек-лист: каталог (`/programmes`)

- [ ] Список показывает программы без фильтров — 899 или 900 (может
      отличаться на 1 из-за скрытых по `missed_runs`, см. `pipeline/README.md`).
- [ ] Фильтры по отдельности и в комбинации реально сужают список: вуз,
      город (10 вариантов), язык обучения, форма обучения, «только
      бюджетные места», направление (10 категорий интересов — это НЕ то же,
      что 892 направления из раздела 4, это упрощённая группировка для
      анкеты).
- [ ] Поиск текстом по названию программы/вуза работает.
- [ ] Сортировка A–Z / Z–A / по вузу.
- [ ] Вкладки по уровню (бакалавр/магистр/доктор/колледж) — числа в
      скобках совпадают с реальным количеством.
- [ ] «Показать ещё» подгружает следующую порцию, не теряя текущий фильтр.
- [ ] На карточке каждой программы — язык, город, форма, длительность,
      значок уровня.
- [ ] Мобильная раскладка — фильтры скрыты за раскрывашкой «Filtri»/«Filters».

## 7. Чек-лист: карточка программы (`/programmes/[вуз]/[программа]`)

- [ ] Открыть **программу с подтверждённой формулой** (например, любую
      программу LU или RSU) и **программу без формулы** (например, что-то
      из вуза, не входящего в список из раздела 4) — сравнить, что вторая
      честно говорит «формула не разобрана», а не показывает пустой
      калькулятор.
- [ ] Поля: уровень, язык, форма, длительность, город, финансирование,
      стоимость в год, число бюджетных мест, дата аккредитации (если есть).
- [ ] Метка источника: «Verified DD.MM.YYYY» или «Auto-extracted — проверьте
      на сайте вуза» — у ЛЮБОЙ программы сегодня это всегда «Auto-extracted»
      для самой программы (программы как таковые ещё не подтверждаются
      человеком отдельно от формулы, см. предложение №07 в разборе
      бизнес-процессов — это уже готовая инфраструктура, но подтверждённых
      программ пока 0).
- [ ] Блок «Что стало с выпускниками» — показывается, только если
      направление программы подтверждено (пока таких 0 — см. раздел 4),
      поэтому сегодня этот блок нигде не должен появляться. Если он всё же
      где-то виден — вот это уже стоит проверить отдельно.
- [ ] Ссылка «Официальный источник» ведёт на реальную страницу вуза.
- [ ] Ссылка на календарь подачи — для Turība должна показать даты (2
      строки в разделе 4 из справочника), для остальных — «даты ещё не
      подтверждены».

## 8. Чек-лист: калькулятор (`/programmes/.../calculator`)

- [ ] Открыть у программы с подтверждённой формулой (LU/RSU/Ventspils/RTU).
- [ ] Поля ввода соответствуют реальным слагаемым формулы (посмотреть,

- [ ] Если у слагаемого есть минимальный порог (gate) — предупреждение

- [ ] Открыть калькулятор для программы **без** подтверждённой формулы
      (прямым переходом по URL) — должно быть честное сообщение, а не
      пустая форма или ошибка.

## 13. Чек-лист: внутренняя очередь (`/verification`)

Не часть продукта ни для одной аудитории — рабочий инструмент, латышский
без перевода, `noindex`. Тем не менее стоит проверить, раз это единственная
страница, показывающая реальное состояние всех неподтверждённых фактов:

- [ ] Дата последнего успешного полного сбора — должна честно показывать
      «ещё не было» (раздел 4 — ни одного полного успешного сбора за всю
      историю).
- [ ] Секция «Apstiprinātas formulas» — 72/101, с разбивкой по вузам.
- [ ] Секция «Nepieciešamie eksāmeni» — 139 записей, сгруппированных по
      программам.
- [ ] Секция «Pieteikšanās termiņš» — 2 записи (обе Turība).
- [ ] Секция «Uzņemšanas veids» — 4 записи.
- [ ] Секция «Programmu virzieni» — 892, сгруппированные по вузу.
- [ ] Секция «Strīdīgs» — 1 запись (Ventspils Elektronikas inženierija).
      **Если миграция из раздела 0 ещё не применена**, под причиной будет
      виден полный текст формулы — это единственное известное расхождение
      с намеренным поведением, ждёт вашего действия, не бага в коде.
- [ ] Порядок внутри каждой секции — вузы с ближайшим известным
      (подтверждённым) сроком подачи должны идти первыми; сегодня видимого
      эффекта нет (см. `src/lib/verification-queue.ts`, комментарий) —
      сработает, когда подтвердится срок вуза с реальными формулами.
