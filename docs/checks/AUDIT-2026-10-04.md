## 3. Решения за владельцем

- В Supabase Auth открыта регистрация (`disable_signup: false`), хотя входа на
  сайте нет. Выключается в панели: Authentication → Sign In / Providers.
- `/verification` открыта всем; `robots.txt` перечисляет её адрес. Закрыть
  авторизацией или убрать строку из `robots.txt` (достаточно `noindex`).
- Поле `verified_by` читается через публичный API и содержит ник и служебные
  пометки (72 формулы, 892 разметки направлений).
- Полная копия базы хранится артефактом GitHub 90 дней; видимость репозитория
  агент проверить не мог. Если репозиторий публичный — сократить срок или шифровать.
- В `.env.local.example` лежит настоящий публичный ключ; он не секрет, но в
  примере уместнее плейсхолдер.

## 4. Где агенты ошиблись

| Утверждение | Что на самом деле |
|---|---|
| «Все публичные страницы грузят HeroUI через `HeroUIProvider`» | Замер: на публичные страницы попадает обёртка в 9,3 КБ; полный HeroUI — только на калькуляторе, `/match`, анкете. Правило 4 соблюдается. |
| «В `.env.local` включён `MATCH_FIXTURE=1`» | Активной строки нет; приёмка шла на настоящих формулах. |
| «`/match` показывает неполный балл ЛУ International Finance как полный» | Слагаемое вступительного испытания в подтверждённой формуле необязательное, шкала у программы своя. Расчёт верен; неясна только подача. |

## 5. Что не проверено

- Настоящий телефон на медленной сети; точная задержка отклика на нажатия.
- Настоящий экранный диктор и контраст (axe агентам запускать запрещалось;
  `npm run test:a11y` в тот же день — 26 сценариев без нарушений).
- Поведение сайта при недоступной базе.
- Заголовки и страницы ошибок рабочей сборки (безопасность проверялась на dev-сервере).
- Уязвимости Python-зависимостей (`pip-audit` не установлен).
- Права anon на UPDATE/DELETE подтверждены чтением политик, а не запросом: проба
  по несуществующей строке неинформативна, по настоящей — запрещена.
