## 3. Решения за владельцем

Владелец ответил по всем пяти 2026-10-10.

- **Регистрация в Supabase Auth** (`disable_signup: false`, хотя входа на сайте
  нет). Решение: выключить. В `supabase/config.toml` выключено; на рабочем
  проекте это делает владелец в панели — Authentication → Sign In / Providers →
  Allow new users to sign up. **Ждёт действия владельца;** проверить можно без
  входа: адрес `…/auth/v1/settings` должен отдать `disable_signup: true`.
- **`/verification` в `robots.txt`.** Решение: строку убрать, страницу не
  закрывать. Сделано: `robots.txt` больше не называет адрес, от индексации
  страницу закрывает `noindex, nofollow` в её метаданных (проверено на сайте).
- **Поле `verified_by` в публичном API** (ник и служебные пометки). Владелец
  ответил «да» — скрыть. **Не сделано, вопрос возвращён владельцу:** при
  проверке выяснилось, что репозиторий публичный, а снимок подтверждённых
  фактов `docs/backups/verified-facts.json` лежит в нём вместе с этим полем.
  Скрыть поле только в API — ничего не скрыть; убрать его из снимка — потерять
  возможность восстановить подтверждения.
- **Полная копия базы в артефактах GitHub.** Решение: сократить срок. Сделано:
  14 дней вместо 90 (`backup.yml`). Видимость репозитория, которую агент аудита
  проверить не мог, проверена 2026-10-10: **репозиторий `gvasiks/studet`
  публичный** — артефакт может скачать любой вошедший пользователь GitHub.
  Секретов в репозитории и его истории не найдено (сервисный ключ, личный ключ
  PostHog, строки подключения, хеши паролей, закрытые ключи).
- **Настоящий публичный ключ в `.env.local.example`.** Решение: оставить. Ключ
  публичный по назначению (он же уходит в браузер каждому посетителю).
