# Studet — обзор проекта

Снимок состояния на 2026-09-16. Это не план и не рабочие инструкции для
ИИ — то и другое уже есть отдельно (см. «Где смотреть подробности» в
конце). Здесь — что проект такое, что в нём реально работает сейчас и
чего ещё не хватает.

## Что это

Веб-сервис, помогающий выпускникам латвийских школ выбрать вуз и
специальность на 2027 год. Строится строго последовательно для двух
разных аудиторий, а не параллельно для обеих:

- **Аудитория А (сейчас, бесплатно)** — местные абитуриенты. Вопрос:
  «что мне подходит и куда я реально прохожу». Путь: анкета → каталог
  → калькулятор конкурсного балла → (в будущем) живой конкурс в дни
  подачи документов.
- **Аудитория Б (позже, платно)** — иностранные абитуриенты. Вопрос:
  «во что обойдётся год и что нужно собрать». Пока не начата.

Три даты выпуска и решения бизнес-анализа, стоящие за ними, — в
`CLAUDE.md`.

## Что реально работает сейчас

### Каталог

- **22 вуза** (11 государственных, 11 частных), **483 программы**.
- Данные собирают 23 источника на Python
  (`pipeline/src/sources/*.py`) — по одному Playwright-скрейперу на
  сайт вуза, либо альтернативный источник, если сайт вуза непригоден
  (Vidzemes Augstskola собирается через NIID.lv, государственную базу
  образовательных возможностей — собственный сайт вуза оказался
  структурно пустым).
- Ни один факт не помечается «подтверждённым» автоматически —
  `verified_at` выставляет только человек через Supabase Studio.
- Известные пробелы: у RTU и LU каталог покрыт не полностью (у LU
  целиком отсутствует факультет точных наук — баг сборщика ссылок,
  задача уже выделена отдельно); полей `application_deadline` никто
  не собирает, хотя они есть в схеме с самого начала.

### Калькулятор конкурсного балла

- **35 программ** (Ventspils Augstskola — 7, Latvijas Universitāte —
  26, RTU — 2) считают по формуле, извлечённой из **утверждённых
  документов о приёме** конкретного вуза, а не со страницы сайта
  (правило 6 `CLAUDE.md` — у RTU, например, две разные страницы сайта
  когда-то давали разные коэффициенты для языка).
- Один общий вычислитель на все вузы (`src/lib/formula.ts`, ~80
  строк) — всё, чем вуз отличается от другого, живёт в данных
  (`formula` / `formula_term` / `formula_gate`), не в коде.
- **0 формул подтверждены человеком** (`verified_at` пуст везде) —
  до публичного запуска это нужно сделать вручную через Supabase
  Studio, автоподтверждения в проекте нет и не будет.

### Публичные страницы

| Маршрут | Что там |
|---|---|
| `/` | Главная, книжная иллюстрация |
| `/programmes` | Каталог с фильтрами: вуз, город (чекбоксы), язык, форма обучения, только бюджет |
| `/programmes/[university]/[programme]` | Карточка программы |
| `/programmes/[university]/[programme]/calculator` | Калькулятор балла (виден только если есть формула) |
| `/survey` | Анкета из 6 шагов → ведёт в каталог с готовыми фильтрами |
| `/favorites` | Список избранного / сравнение программ — только в `localStorage`, без регистрации |

Обе локали (`/lv`, `/en`) есть на каждом маршруте, переключатель языка
— в шапке, сохраняет текущую страницу.

### Чего ещё нет

- **GitHub remote не настроен** — автообновление каталога через
  GitHub Actions существует только как файл воркфлоу, не как реальный
  процесс; все прогоны конвейера пока вручную.
- **PostHog и Resend** упомянуты в стеке (`CLAUDE.md`), но нигде не
  подключены — ни аналитики воронки, ни писем-напоминаний.
- **SEO** — нет `robots.txt`/`sitemap.xml`, на карточке программы нет
  meta description, только `<title>`. При том что весь заявленный
  канал роста — поисковая выдача (правило 4 `CLAUDE.md`).
- `public/images/hero-bg.png` — 2,8 МБ, не оптимизирован, стоит с
  `priority` на главной странице — реальный риск для LCP.
- Категории интересов в анкете (шаг 2) — черновик, не сверен с
  тестами профориентации (ГАРО), как и было отмечено с самого начала
  бизнес-анализа.

## Архитектура

```
Next.js 16 (App Router, Turbopack)         Python 3.14 + Playwright
  ├─ публичные страницы:                     │
  │  серверный рендер, обычный Tailwind      │  15 скрейперов сайтов вузов
  │  (без HeroUI — правило 4)                 │  → Pydantic-модели → пишут
  ├─ интерактив (анкета, калькулятор,         │     напрямую в Postgres
  │  избранное): HeroUI v2 + клиентский JS    │     сервисным ключом
  └─ i18n: свои словари, без next-intl        │
                    │                          │
                    └──────────┬───────────────┘
                               ▼
                  Supabase (Postgres, eu-west-1)
                  RLS на каждой таблице,
                  anon key — у Next.js, service_role — только у конвейера
```

Next.js и Python не общаются по HTTP — только через общую базу
(правило 3 `CLAUDE.md`). Next.js делает всё, что видит пользователь,
включая сам расчёт балла (ради индексации на серверных страницах);
Python — всё, что без пользователя: обход сайтов, извлечение,
снимки статистики.

### Модель данных (основное)

- `university`, `programme` — сам каталог, с `source_url` и
  `verified_at` на каждом факте.
- `formula`, `formula_term`, `formula_gate` — конкурсная формула как
  данные: `formula_term.kind` — `ce` (экзамен), `ce_average`,
  `certificate` (оценка из аттестата) или `entrance_exam`
  (вступительное испытание); `subject` — не только предмет ЦЭ, но и
  метка конкретного испытания, если их в одной формуле несколько
  (RTU Rīgas Biznesa skola: тест английского + собеседование + тест
  математики — три разных числа в одной формуле).
- `level_coefficient` — коэффициенты уровня ЦЭ (augstākais/
  optimālais/vispārīgais), одна таблица на все вузы, потому что
  задаются не вузом, а общим нормативным актом.

## Где смотреть подробности

- **`CLAUDE.md`** — рабочие правила, ограничения проекта и решения
  бизнес-анализа. Первое, что стоит прочитать, если продолжаете
  разработку с ИИ.
- **`docs/PLAN.md`** — исходный детальный план по разделам; местами
  устарел, актуальные отклонения помечены блоками «Обновление
  сентября 2026» прямо внутри текста.
- **`README.md`** — команды для локальной разработки, настройка
  Supabase.
- **`pipeline/README.md`** — как запустить Python-конвейер локально.
