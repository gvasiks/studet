## 2. Секреты в GitHub Actions — что они дают и где хранятся

Список — только имена и назначение, не значения (значения — в GitHub Settings,
доступны только владельцу репозитория с правами Admin).

| Секрет | Используется в | Даёт доступ к |
|---|---|---|
| `SUPABASE_URL` | `backup.yml`, `pipeline-health.yml`, `scrape-catalog.yml` | Адрес проекта Supabase (не секрет сам по себе, но нужен вместе со следующим) |
| `SUPABASE_SERVICE_ROLE_KEY` | те же три | Полный доступ к базе в обход RLS — самый чувствительный секрет проекта (CLAUDE.md, A02). Никогда не должен попасть в код `src/` или в публичный лог |
| `SUPABASE_DB_URL` | `backup.yml` | Прямое подключение к Postgres для `pg_dump` (полный дамп схемы в артефакт прогона). Ещё не добавлен владельцем на 2026-09-25 |
| `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` | `ci.yml` | Публичный (publishable) ключ — тот же, что в собранном сайте у любого посетителя; безопасен для утечки по конструкции (ограничения через RLS), но нужен, чтобы сборка вообще прошла |

**Если `SUPABASE_SERVICE_ROLE_KEY` скомпрометирован** (утёк, ушёл не туда): в
Supabase Dashboard → Settings → API → Reset service_role key. После сброса
обновить секрет в GitHub — иначе все три воркфлоу начнут падать с ошибкой
авторизации (это шумно, но не опасно — просто чинится).

## 3. Что работает автоматически и как это остановить

Все четыре — обычные GitHub Actions, отключаются одинаково: репозиторий →
вкладка **Actions** → выбрать workflow в списке слева → кнопка **⋯** →
**Disable workflow**. Включить обратно — та же кнопка, **Enable workflow**.
Ничего не нужно менять в коде.

| Workflow | Расписание | Что делает | Когда стоит остановить |
|---|---|---|---|
| `scrape-catalog.yml` | Понедельник, 01:00 UTC | Обходит 25 источников, обновляет каталог | Если сайт вуза начал отдавать вузу мусор, а парсер это не ловит — до починки, чтобы не портить данные каждую неделю |
| `pipeline-health.yml` | Ежедневно | Проверяет, что последний полный сбор был не позже 9 дней назад, иначе шлёт письмо о сломанном workflow | Практически никогда — сам по себе ничего не пишет в базу, только предупреждает |
| `backup.yml` | Понедельник, через 2 часа после сбора | Снимок подтверждённых фактов в git + `pg_dump` в артефакт | Практически никогда — это единственная защита от потери подтверждений, останавливать в последнюю очередь |
| `ci.yml` | На каждый push/PR | Тесты, линт, сборка, проверка доступности | Не мешает продакшену, можно не трогать вовсе |

**Экстренная остановка всего сразу**: Settings → Actions → General →
"Disable Actions for this repository". Возвращает обратно та же страница.

## 4. Если что-то выглядит сломанным — куда смотреть

1. `/lv/verification` (или `/en/verification`) на живом сайте — дата
   последнего успешного полного сбора видна вверху страницы.
2. GitHub → Actions — красные (упавшие) прогоны видны сразу в списке,
   у каждого есть лог.
3. Supabase Dashboard → Reports — использование базы (место, число
   запросов) и билинг проекта.
4. GitHub → Settings → Billing → Actions — потраченные минуты (см. также
   предложение №5 в разборе бизнес-процессов).
