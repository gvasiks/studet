# Выкладка сайта на свой сервер

Сайт ставится на виртуальный сервер владельца (Ubuntu 24.04, регион ЕС). На
том же сервере работает телеграм-бот — выкладка его не трогает.

Все команды ниже выполняются **на сервере**, под `root`, по SSH. Идите по
шагам по порядку; после каждого шага есть проверка — если она не сходится,
остановитесь и не идите дальше.

## Как это устроено

```
интернет ──► Caddy (порты 80 и 443, сертификат HTTPS) ──► сайт (127.0.0.1:3000)
```

- **Caddy** — веб-сервер. Сам получает и продлевает сертификат.
- **Сайт** — процесс Node.js под отдельным пользователем `studypick` без
  прав администратора. За ним следит systemd: поднимает при старте сервера
  и после сбоя.
- **База** остаётся в Supabase. На сервере нет ничего, чего нет в
  репозитории или в Supabase, кроме одного файла настроек.

| Что | Где на сервере |
|---|---|
| Код сайта | `/srv/studypick/app` |
| Настройки | `/etc/studypick/env` |
| Node.js для сайта | `/opt/node24` |
| Служба | `/etc/systemd/system/studypick.service` |
| Настройка Caddy | `/etc/caddy/Caddyfile` |

## Чем жертвуем

- Один сервер — одна точка отказа. Если он недоступен, недоступен сайт.
- Систему обновляете вы (в Ubuntu обновления безопасности ставятся сами,
  но перезагружать сервер после обновления ядра надо руками).
- Во время обновления сайта (около минуты) он может отвечать ошибками.
- Июльский пик надо проверить нагрузкой в июне — так записано в правилах
  проекта.

## Шаг 1. Отдельный Node.js для сайта

На сервере уже стоит Node.js 20 — им пользуется бот, его не трогаем. Его
поддержка закончилась в 2026 году, поэтому сайту ставится свой Node.js 24
в отдельную папку.

```
cd /tmp
curl -fsSLO https://nodejs.org/dist/v24.21.0/node-v24.21.0-linux-x64.tar.xz
curl -fsSLO https://nodejs.org/dist/v24.21.0/SHASUMS256.txt
sha256sum -c --ignore-missing SHASUMS256.txt
```

Последняя команда должна ответить `node-v24.21.0-linux-x64.tar.xz: OK`.
Если ответ другой — файл скачался с ошибкой, дальше не идти. (Контрольная
сумма на 2026-10-09 начиналась с `fd8e59d5` и заканчивалась на `cb2d6`.)

```
tar -xJf node-v24.21.0-linux-x64.tar.xz -C /opt
ln -sfn /opt/node-v24.21.0-linux-x64 /opt/node24
/opt/node24/bin/node -v
```

Проверка: напечатано `v24.21.0`. Команда `node -v` без пути по-прежнему
показывает `v20…` — так и должно быть.

## Шаг 2. Пользователь и папки

```
useradd --system --create-home --home-dir /srv/studypick --shell /usr/sbin/nologin studypick
mkdir -p /etc/studypick
apt update
apt install -y git
```

## Шаг 3. Код

```
runuser -u studypick -- git clone https://github.com/gvasiks/studet.git /srv/studypick/app
```

Проверка: `ls /srv/studypick/app/deploy` показывает этот файл.

## Шаг 4. Настройки

```
cp /srv/studypick/app/deploy/env.example /etc/studypick/env
nano /etc/studypick/env
```

Заполните две пустые строки — адрес базы и публичный ключ. Значения те же,
что в `.env.local` на вашем компьютере (`NEXT_PUBLIC_SUPABASE_URL` и
`NEXT_PUBLIC_SUPABASE_ANON_KEY`). Остальное уже заполнено.

**Не добавляйте** в этот файл служебный ключ базы (`SUPABASE_SERVICE_ROLE_KEY`)
и флаг предпросмотра стран (`NEXT_PUBLIC_PREVIEW_COUNTRIES`).

```
chown root:studypick /etc/studypick/env
chmod 640 /etc/studypick/env
```

## Шаг 5. Служба и первая сборка

```
cp /srv/studypick/app/deploy/studypick.service /etc/systemd/system/studypick.service
systemctl daemon-reload
systemctl enable studypick
bash /srv/studypick/app/deploy/update.sh
```

Скрипт ставит зависимости, собирает сайт и запускает службу; первая сборка
занимает несколько минут.

Проверка: в конце написано «Готово: сайт отвечает». Ещё одна:

```
curl -s http://127.0.0.1:3000/robots.txt
```

Должно быть `Disallow: /` — сайт закрыт от поисковиков.

Если скрипт остановился со словами «Сборка остановлена» — в файле настроек
чего-то не хватает, в сообщении сказано чего.

## Шаг 6. Веб-сервер

```
apt install -y caddy
cp /srv/studypick/app/deploy/Caddyfile /etc/caddy/Caddyfile
```

Пока домен не указывает на сервер, Caddy не сможет получить сертификат —
поэтому сначала шаг 7, потом перезапуск Caddy.

## Шаг 7. Домен

У регистратора домена (`eu.myzone.app`) в разделе DNS создайте две записи
типа **A**:

| Имя | Значение |
|---|---|
| `studypick.eu` (или `@`) | IPv4-адрес сервера из панели провайдера |
| `www` | тот же адрес |

Изменение расходится от нескольких минут до нескольких часов. Проверка на
сервере:

```
getent hosts studypick.eu
```

Когда команда показывает адрес вашего сервера:

```
systemctl restart caddy
systemctl --no-pager --lines=15 status caddy
```

Проверка: с любого компьютера открывается `https://studypick.eu/lv`, в
адресной строке — замок.

## Шаг 8. Пароль на время закрытой выкладки (советую)

Запрет для поисковиков не мешает открыть сайт человеку, который знает
адрес. Чтобы до запуска его видели только вы и участники закрытой проверки:

```
caddy hash-password
```

Введите пароль дважды, скопируйте строку, которая начинается с `$2a$`.

```
nano /etc/caddy/Caddyfile
```

В блоке `basicauth` уберите три решётки и вставьте строку вместо слова
`ХЕШ`. Затем:

```
systemctl reload caddy
```

Проверка: сайт спрашивает имя (`studypick`) и пароль.

## Шаг 9. Сетевой экран (по желанию)

Сначала посмотрите, что уже настроено:

```
ufw status
```

Если написано `Status: inactive` и вы хотите его включить — **сначала**
разрешите SSH, иначе закроете себе вход на сервер (спасёт только консоль
VNC в панели провайдера):

```
ufw allow OpenSSH
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

Если не уверены, как устроен вход на сервер, — пропустите этот шаг.

## Обновление сайта

После каждого изменения в репозитории:

```
bash /srv/studypick/app/deploy/update.sh
```

## Если что-то не работает

| Что видно | Где смотреть |
|---|---|
| Сайт не открывается вовсе | `systemctl status caddy` и `journalctl -u caddy -n 50 --no-pager` |
| Открывается ошибка 502 | сайт не запущен: `journalctl -u studypick -n 50 --no-pager` |
| Замка нет, сертификат не получен | домен ещё не указывает на сервер: `getent hosts studypick.eu` |
| Бот перестал работать | выкладка его не трогает; проверьте, что `node -v` по-прежнему `v20…` |

## День запуска

1. В `/etc/studypick/env`: убрать строку `SITE_CLOSED=1`, добавить
   `NEXT_PUBLIC_POSTHOG_KEY=…` (счётчик посещений).
2. В `/etc/caddy/Caddyfile`: вернуть решётки перед блоком `basicauth`,
   затем `systemctl reload caddy`.
3. Запустить `bash /srv/studypick/app/deploy/update.sh`.
4. Проверить: `curl -s https://studypick.eu/robots.txt` показывает
   `Allow: /` и строку `Sitemap:`.

Остальные шаги публикации (ссылка на политику в подвале и другое) —
`docs/PRIVACY-CHECKLIST.md`, раздел 4.
